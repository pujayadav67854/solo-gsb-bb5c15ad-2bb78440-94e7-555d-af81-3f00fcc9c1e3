# 事故证据链编排器（Evidence Chain Orchestrator）

用「必须早于」约束编排事故证据：每次连线都会校验有向图，合法连线按拓扑层级自动重排为**可解释时间线**；若连线构成环，则**拒绝保存**并高亮完整冲突闭环；还可对约束做**传递约简瘦身**，安全剔除冗余连线；另有只读的**时间窗口分析**，在事故时间区间内沿 DAG 双向传播每张卡片的最早 / 最晚可行时刻。

技术栈：**React 18 + TypeScript + Vite**（前端） · **Express + better-sqlite3**（后端） · 单容器交付。

## 功能

- 证据卡片：创建 / 编辑 / 删除（标题、来源、发生时间、描述）
- 重复证据合并：工具栏进入「合并重复证据」模式，先点**源卡片**（合并后删除）再点**保留卡片**；确认后在单个事务内把源卡的全部入边、出边改接到保留卡（重复连线只留一条），再删除源卡，保留卡的标题、来源、时间和描述均不变。若改接会产生自环或有向环，返回当前图中的冲突路径并**整体拒绝**（事务回滚，高亮冲突路径）
- 「必须早于」连线：拖拽卡片上的「⇢ 连线」到目标卡片，或点击连线按钮后再点击目标卡片
- 有向图校验：每次连线在服务端做环检测；成环时返回完整闭环（HTTP 409），前端将闭环中的卡片与已有连线标红、被否决的新边以红色虚线动画展示
- 拓扑分层时间线：合法连线后按 Kahn 最长路径分层自动重排为「层级 1 → 层级 N」的时间线列
- 可解释侧栏：每个层级列出卡片及其「需等待」的直接前置证据，并附完整约束清单
- 约束瘦身（传递约简）：服务端分析出「忽略自身后仍可达」的冗余连线并给出最短替代路径；瘦身面板逐条展示，点击后在画布上同时高亮原连线（琥珀色）与替代路径（绿色）；确认后批量移除——单个事务内逐条复核「当前仍冗余」才删除，所有证据间的可达关系保持不变
- 顺序确定性查询：在「顺序确定性查询」面板任选两张证据卡片，服务端判定「A 必须早于 B」「B 必须早于 A」或「顺序未被约束」；前两种情况返回一条最短约束路径，可一键在画布上以青色高亮依据路径；未约束时分别生成「A 在 B 前」「B 在 A 前」两个合法拓扑序作为双向见证（并列节点按创建时间、再按 id 稳定排序），可按任一见证临时预览画布布局（青色虚线为临时见证约束），退出预览后恢复原布局，全程不写数据库
- 必经证据分析：在「必经证据分析」面板选定起点 A 与终点 B，仅当 A 能沿现有「必须早于」连线到达 B 时，服务端找出**所有 A→B 路径共同经过的中间卡片**（必经证据），按约束先后展示，可一键在画布上以粉色高亮起终点与必经卡片；对位于某条 A→B 路径但并非必经的卡片，可点击核出一条**绕开它的真实路径**（画布橙色高亮、被绕开卡片淡显）；有直接连线时必经中间卡片为空，A 无法到达 B 时明确说明。分析全程只读，卡片或连线变化后结果自动刷新
- 时间窗口分析（只读）：在「时间窗口分析」面板输入**事故起止时间**（闭区间）与**至少 1 分钟的整数最小间隔**。所有卡片都须落在该区间内，已有发生时间作为固定时刻，每条「必须早于」连线要求后卡至少晚于前卡该间隔；服务端沿现有有向无环图**双向传播时间上下界**（正向沿拓扑序推下界、反向推上界），列出每张卡片在所有可行赋时中的**最早、最晚时刻**（固定卡显示同一时刻），空时间卡参与推导，孤立卡仅受事故区间限制。无解时不展示可行窗口，而是返回一条导致上下界冲突的**真实约束路径及冲突时间**（下界要求的最早时刻与上界允许的最晚时刻），可在画布以红色高亮整条路径、冲突卡片脉动；固定时刻越出事故区间时不做传播并**定位该卡片**。无效时间、倒置区间、非法间隔（非整数或小于 1 分钟）在前后端双侧拒绝。分析不改写任何卡片或连线，图或输入变化后旧结果自动清除
- 导入 / 导出 JSON 快照：点「导入 JSON」选择文件后，**服务端先做只读差异预览**——沿用导入校验解析文件，按证据 id 比较标题、来源、发生时间、描述，按连线两端 id 比较，列出新增 / 删除 / 修改的卡片与新增 / 删除的连线（含数量，无 id 卡片视为新增），明细可展开查看；预览只读不写库，可「取消」或「确认导入」。确认时在**单个事务内重新校验**：预览须未过期、文件内容与当前图都和预览时一致、快照重新解析后仍合法且无环——任一变化即拒绝覆盖并提示重新预览（HTTP 409），全部通过才整体替换。含环快照在预览阶段就整体拒绝（HTTP 422）
- 内置示例事故（2026-03 支付网关宕机），首次启动自动载入，也可随时一键重置

## 快速开始（Docker，单条命令）

```bash
docker compose up --build
```

然后访问入口 **http://localhost:8080**（服务端口 8080，数据持久化在命名卷 `evidence-data` 中）。页面顶部工具栏下方依次为「顺序确定性查询」「必经证据分析」与「时间窗口分析」面板，画布与「时间线解读」侧栏位于其下。

不使用 Compose 时：

```bash
docker build -t evidence-chain . && docker run -p 8080:8080 -v evidence-data:/data evidence-chain
```

## 导入 JSON 快照

1. 浏览器打开 **http://localhost:8080**，点击工具栏「导入 JSON」并选择快照文件（可用「导出 JSON」先得到一份）。
2. 服务端立即沿用导入校验解析文件并做环检测，弹出**只读差异预览**：
   - 顶部汇总新增 / 修改 / 删除卡片与新增 / 删除连线的数量；
   - 按证据 id 比较标题、来源、发生时间、描述，按连线两端 id 比较连线；快照中没有 id 的卡片一律视为**新增**；
   - 各分组可展开查看明细（修改卡片逐字段展示「旧值 → 新值」，空值显示「（空）」）。
3. 预览不会改动任何数据：点「取消」放弃导入，或点「确认导入并整体替换」提交。
4. 确认时服务端在**单个事务内重新校验**预览绑定的「当前图 + 文件内容」：若预览已过期、文件被换过或预览期间证据链发生了变化，返回 409 并提示重新预览（弹窗内可直接「重新预览」），不会覆盖任何数据；校验通过才整体替换。
5. 含环快照在预览阶段就返回 422 并给出闭环，无法进入确认。

## 本地开发

要求 Node.js ≥ 20。

```bash
npm install        # 安装全部 workspace 依赖
npm run dev        # 同时启动后端(8080)与前端 Vite(5173，代理 /api)
```

访问 http://localhost:5173 。


| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/state` | 全量状态：证据、连线、拓扑层级 |

| PUT | `/api/evidence/:id` | 编辑证据卡片 |
| DELETE | `/api/evidence/:id` | 删除卡片（级联删除相关连线） |
| POST | `/api/evidence/merge` | 合并重复证据：body `{ sourceId, targetId }`，单事务内把源卡全部入边/出边改接到保留卡（重复连线只留一条）并删除源卡；改接产生自环或有向环时 `409 { message, merge: { kind, path }, cycle }` 整体拒绝 |
| POST | `/api/edges` | 新建「必须早于」连线；成环返回 `409 { message, cycle }` |
| DELETE | `/api/edges/:id` | 删除连线 |
| GET | `/api/redundancy` | 传递约简分析：`{ redundant: [{ edgeId, fromId, toId, path }] }`，`path` 为最短替代路径 |
| POST | `/api/edges/prune` | 批量瘦身：body `{ edgeIds: number[] }`，单事务内仅删除当前仍冗余的连线，返回最新全量状态（含最新分层）及 `pruned` / `skipped` |
| GET | `/api/order-query?a=<id>&b=<id>` | 顺序确定性查询：`{ relation, path, witnesses }`。`relation` 为 `a-before-b` / `b-before-a` 时 `path` 为最短约束路径；为 `unconstrained` 时 `witnesses` 含 `aFirst` / `bFirst` 双向见证（合法拓扑序 `order` + 预览层级 `levels`） |
| GET | `/api/must-pass?a=<id>&b=<id>` | 必经证据分析（只读）：`{ reachable, direct, mustPass, optional }`。`mustPass` 为所有 A→B 路径共同经过的中间卡片、`optional` 为位于某条路径但可绕开的中间卡片，均按约束先后排序；`reachable=false` 表示 A 无法到达 B，`direct=true` 表示存在 A→B 直接连线（此时 `mustPass` 必为空） |
| GET | `/api/must-pass/bypass?a=<id>&b=<id>&skip=<id>` | 绕开核对（只读）：`{ path }` 为绕开中间卡片 `skip` 的一条最短 A→B 真实路径（含两端点）；该卡片实为必经时 `path` 为 `null` |
| GET | `/api/time-window?start=<时间>&end=<时间>&gap=<整数分钟>` | 时间窗口分析（只读）：在事故闭区间 `[start,end]` 内以 `gap≥1` 分钟为每条连线的最小间隔双向传播时间上下界。`feasible=true` 时返回 `cards:[{cardId,fixed,earliest,latest,...}]`（固定卡 earliest===latest）；无解时 `feasible=false`、`cards` 为空——固定时刻越界返回 `outOfRange:[{cardId,fixedAt,side}]`，否则返回 `conflict:{ pivotId, lowerAt, upperAt, path, lowerAnchor, upperAnchor, ... }`，其中 `path` 为导致上下界冲突的真实约束路径（相邻 id 即图中已有连线），`lowerAt/upperAt` 为冲突时间。无效时间 / 倒置区间 / 非法间隔返回 `400 { message }` |
| GET | `/api/export` | 导出 JSON 快照（附件下载） |
| POST | `/api/import/preview` | 导入差异预览（只读）：body `{ snapshotText }`（文件原文）。服务端沿用导入校验解析并做环检测（含环返回 `422 { message, cycle }`），按证据 id 比较标题 / 来源 / 发生时间 / 描述、按连线两端 id 比较连线，返回 `{ token, diff }`：`diff.addedCards / removedCards / modifiedCards / addedEdges / removedEdges` 明细与 `counts` 数量，无 id 卡片视为新增；`token` 一次性、绑定预览时的当前图指纹与文件内容哈希 |
| POST | `/api/import/confirm` | 确认导入（整体替换）：body `{ token, snapshotText }`。单个事务内重新校验令牌有效性、文件内容哈希与当前图指纹均与预览一致，并重跑解析与环检测；任一变化返回 `409 { message, code: 'import-stale' }` 拒绝覆盖、提示重新预览；格式错误返回 400、含环返回 422 |
| POST | `/api/import` | 兼容旧流程的直接导入（整体替换）：body 为快照对象，同样解析并做环校验；含环返回 `422 { message, cycle }` |
| POST | `/api/seed` | 重置为内置示例数据 |

所有变更类接口均返回最新全量状态，前端直接替换本地状态。

## 环检测与分层算法

- **连线校验**（`server/src/graph.ts`）：新增边 `A → B` 前，沿已有边从 `B` 出发 BFS 寻找回到 `A` 的路径；找到即构成环，返回闭环节点序列 `[A, B, …, A]` 供前端高亮。
- **拓扑分层**：Kahn 算法 + 最长路径分层，`level(n) = max(level(前置)) + 1`，保证每条边都严格从左指向右，层级即「最早可发生轮次」。
- **重复证据合并**（`server/src/graph.ts`）：在当前无环图上，源卡 `s` 合并进保留卡 `t` 后产生自环/有向环，当且仅当 `s` 与 `t` 在当前图中存在直接约束或沿已有边互相可达——直接相连时改接后该边变成 `t→t` 自环（优先判定）；否则 `s ⇝ t` 或 `t ⇝ s` 会在改接后闭合成环，BFS 返回的那条当前图中的真实路径即冲突路径（前端整体标红）。无冲突时制定改接计划：源卡的入边 `x→s`、出边 `s→x` 改接到 `t`，若保留卡已有同方向连线（`x→t` / `t→x`）则删除源侧重复边只留一条，无关节点间连线原样保留。校验、去重、改接、删除源卡均在**单个事务**内执行，冲突即抛错回滚，成功后返回最新分层状态并刷新画布。
- **传递约简（约束瘦身）**：对每条边 `A → B`，在忽略该边自身后 BFS 检查 `A` 是否仍可达 `B`；可达则该边冗余，返回的 BFS 路径即一条最短替代路径。批量移除在**单个事务**中执行：按请求顺序逐条复核该边在剩余边集中是否仍冗余，仅删除仍冗余者——删除冗余边不改变图的传递闭包，因此任意两条证据间的可达关系在瘦身前后完全一致。
- **顺序确定性查询**：`A ⇝ B` 可达则「A 必须早于 B」，`B ⇝ A` 可达则「B 必须早于 A」，均返回 BFS 最短约束路径作为判定依据；互相不可达时顺序未被约束，分别附加一条见证方向边（`A→B` 与 `B→A`）生成两个合法拓扑序作为双向见证。拓扑排序中就绪的并列节点统一按创建时间、再按 id 稳定排序，保证见证结果确定可复现。见证预览仅在前端临时套用附加约束后的层级布局，不写入数据库。
- **必经证据分析**（`server/src/graph.ts`）：中间卡片 `v` 是 A→B 的**必经证据** ⇔ 在删除 `v`（及其相连连线）后的图中 A 不再可达 B。候选集为「从 A 可达 且 能到达 B」的节点（即位于某条 A→B 路径上的节点，正反向各一次 BFS 求得），剔除 A、B 自身后逐一删点复核，把候选集分成必经（`mustPass`）与可绕开（`optional`）两组，并按确定性拓扑序（约束先后）排序输出。绕开核对即「删除该卡片后的 BFS 最短路径」，找到的就是一条绕开它的真实 A→B 路径。分析接口均为 GET 只读，前端在卡片或连线变化后自动重新查询并刷新画布高亮。
- **时间窗口分析**（`server/src/graph.ts`，GET 只读）：设事故闭区间 `[S, E]`、每条连线最小间隔 `g`，对每张卡片维护下界 `lb`（最早可发生时刻）与上界 `ub`（最晚可发生时刻）。先在确定性拓扑序上正向传播：`lb(v) = max(S, v 的固定时刻, max{lb(u)+g : u→v})`；再逆序反向传播：`ub(v) = min(E, v 的固定时刻, min{ub(w)-g : v→w})`。空时间卡参与全部推导，孤立卡得到 `lb=S、ub=E`。固定卡取同一值（`lb=ub=固定时刻`）。逐边松弛对差分约束系统给出紧界：若传播结束后所有卡片均 `lb≤ub`，则逐卡取最早 / 最晚边界都可扩展为全局可行赋时（固定卡显示同一时刻）；否则拓扑序中首个 `lb>ub` 的卡片即为冲突点，取其**下界见证链**（从区间起点或某固定锚点沿真实连线逐段加 `g`）与**上界见证链**（沿反向连线到区间终点或固定锚点）拼成一条真实约束路径，并同时给出冲突时间 `lb`（下界要求的最早时刻）与 `ub`（上界允许的最晚时刻）供画布高亮。固定时刻越出闭区间（`<S` 或 `>E`，端点视为合法）优先检出并定位该卡片，此时不做上下界传播。所有时间统一在墙钟分钟轴上计算，无时区输入按字面量、带时区输入换算到同一轴，结果按分钟精度回传，不受服务器时区影响。分析不写数据库，前端在图或输入变化后清除旧结果与高亮。
